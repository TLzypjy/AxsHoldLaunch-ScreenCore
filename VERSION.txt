版本：2.0.5+beautify.115

beautify.115 变更（修复 .114 shader 编译错误）：
- .114 删重复声明后仍编译失败：openMode 分支内 "float inv = 1.0-motion;" 笔误，
  分支内变量名是 motionO。改为 1.0-motionO。失败原因由 .114 新加的
  sMsdFailReason 持久化日志直接暴露（诊断机制首次立功）。

beautify.114 变更（修复 .113 全部动画失效）：
- 根因：.113 往 shader 加 openMode 分支时，Edit 误把 cell/grid/unit/corner/r/r2/r3/r4
  九行声明复制了一份在分支后面——MSL 同一作用域不允许同名重复声明，运行时
  newLibraryWithSource 编译失败，管线建立失败（sMsdTried 缓存），消散+呼出全部
  静默失效（详细原因日志被 512KB 轮转吃掉，只余 "metal unavailable"）。
- 修复 1：删除重复声明，openMode 分支保持在 r4 声明后（变量全部就位）。
- 修复 2：ensurePipeline 失败原因持久化到 sMsdFailReason，后续每次
  "metal unavailable -> no dissolve effect (%@)" 都带具体原因，不再怕日志轮转。

beautify.113 变更（ARC 呼出聚合动画 + 独立开关）：
- 需求（用户决策）：先做 B 方案粒子反向聚合，生效范围仅 ARC 菜单呼出（全屏转浮窗后续再做），独立开关。
- Metal：DustUniforms 增加 openMode 字段；nlDustVertex 顶部 openMode==1 分支——
  消散彩砂时间线倒放：粒子从右上散布态（缩至 24%~56%、隐身）向卡片框架收拢、渐显，
  聚合完成后由调用方显示真卡片；公共入口重构为 axs_metalPlayCommon，
  对外 axs_metalSandPlay（消散）+ axs_metalAssemblePlay（呼出聚合）两个包装。
- 呼出探测：无已知签名的 open selector，改用 SCFloatingContainerView 可见性变迁检测——
  hook setHidden: / didMoveToWindow（子类安全模式：自身声明则子类级 MSHook，
  仅继承则 class_addMethod + msgSendSuper 转发，绝不污染 UIView 全局）。
  判定 = 消失 ≥0.4s 后重新可见且窗口非空、尺寸 >40pt；消散自身的恢复显示用
  axs_open_lastDismissHide 3 秒窗口抑制；快速切换（<0.4s，dock 往返）忽略。
- 流程：呼出 → 0.12s 后（首帧布局落定）截图 → 隐藏真卡片 → 聚合 0.85s×密度 → 恢复真卡片。
- 独立开关 splitBeautifyOpenAnimEnabled（默认开），面板「呼出聚合动画 / Open Assemble Animation」
  带 info 说明，插在消散动画开关之后。

- 用户决策：新增密度滑块后，CPU 路径靠上限防卡顿是倒设计 → 8 种 UIView 网格样式
  全部迁入 Metal vertex shader，UIView CPU 路径彻底退役（Metal 不可用=无消散，
  卡片原生关闭，不再有 CPU 兜底）。
- shader：DustUniforms 增加 style 字段，nlDustVertex 按 style 分支——
  0 方块飞散（随机四向溅射-40pt 上偏，ease-out）
  1 重力下落（ease-in，dy 80~220）
  2 漩涡吸入（径向穿心+切向 90~160，缩到 0）
  3 冲击波（径向炸开，按到心距离延迟 len/320）
  4 灰尘飘散（上浮-60~-170 + 横漂）
  5 像素溶解（原地，随机延迟 0~0.7）
  6 百叶窗（按行 0.6s 递进，±16pt 横移）
  7 玻璃碎裂（随机溅射+90pt 下坠，ease-in，强旋转）
  8 彩砂（保留 .104 参考模型原样）
  ease 曲线对应 UIView 的 EaseOut/EaseIn（quad 近似）；styles 0-7 breakage=0 保持方片。
- 密度：splitBeautifyDismissDensity（0.5~3.0，step 0.1，默认 1.0）——
  彩砂 grains=14000×密度（上限 40000）；网格样式 cols/rows=基准网格×密度（上限 240）。
  基准网格照抄原 gridForStyle：Dust14/14、Pixel12/12、Blinds8/14、Glass5/6、其余10/10。
- 时长：axs_dm_styleBaseDuration 每样式基准时长表（0.87/1.20/1.03/1.83/1.55/0.88/0.85/1.03/1.30），
  与 shader 内 begin/span 分母逐字对应，速度滑块照旧缩放整体时间线。
- 删除：axs_dm_emitColorSand、UIView 网格路径、axs_dm_randRange/dustHash/gridForStyle、
  overlay 全局变量；trigger 隐藏卡片逻辑不变。

beautify.111 变更（消散双重画面修复 + 速度滑块连续步进）：
- 问题 1：消散时除粒子外，原卡片本体还在跑 ScreenCore 自己的关闭动画（向右下角收走），
  形成双重画面（视频帧 t=6.00 证实）。
  修正：axs_dm_emitColorSand / axs_dm_emitParticlesFromView 改为返回「特效是否真正启动」，
  trigger 在特效成功启动后立刻隐藏原卡片（container.hidden=YES），原生关闭动画继续在
  隐藏态跑完不受影响；消散清理完成后（1.9*speed+0.3s）恢复 hidden=NO 作保险，
  防止容器被复用时残留隐藏态。
- 问题 2：消散速度滑块只能 0.3/1.3/2.3/3.0 跳变——SCLabeledSliderCell 支持 step 键
  （原生倾斜角度滑块即 step=0.5），我们漏配了，默认步进 1.0。
  修正：splitBeautifyDismissSpeed 增加 step=0.1。

beautify.110 变更（消散卡片上下颠倒修复：去掉纹理上传的双重翻转）：
- 现象：.109 起 Metal 引擎真正生效，但消散时整张浮窗快照上下镜像（计算器 "0 . =" 行跑顶部、
  AC/+−/%/÷ 跑底部，数字垂直翻转）。
- 根因：axs_msd_makeTexture 里 .104 时代遗留的 TranslateCTM+ScaleCTM(1,-1) 手动翻转是多余的。
  原生 CGBitmapContext 坐标系 y 向上、内存第 0 行即缓冲区顶部，快照 CGImage 栅格自顶向下，
  直接绘制就已经是「纹理行 0 = 图片顶部」，与 shader 的 uv.y 映射（行 0 = 卡片顶部）一致；
  再叠加翻转反而翻反。UIView 回退路径不走这段，故直到 .109 Metal 生效才暴露。
- 修正：删除该翻转，直接 CGContextDrawImage；日志模块版本串从遗留的 beautify.97 更新为 .110；
  CI 断言禁止 TranslateCTM/ScaleCTM(1,-1) 回归。

beautify.109 变更（隐根包功能修复：改用官方 RootHide Patcher 转换）：
- 现象：.108 手工隐根包安装后 ScreenCore 自身功能失效（右下角 Arc 菜单呼不出）。
- 对照官方 roothide/RootHidePatcher patch.sh（b3e04a4aaa98，GPL-3）发现手工重排缺三件事：
  a) Mach-O rpath 重写 /var/jb/X → @loader_path/.jbroot/X；b) ldid 重新签名；
  c) AutoPatches 模式（即机内转换 App 的「Rootless 兼容层」开关）写入
     <mach-o>.roothidepatch 标记 + Pre-Depends: rootless-compat，
     由 bootstrap 的 Dynamic Patch Framework 在加载期做路径重映射。
- 修正：官方 patch.sh 入库（packaging/roothide/patch.sh + roothide.entitlements，
  仅 -Zzstd→-Zxz 以适配 CI 的 brew dpkg），打包脚本第 8 步直接调用它 AutoPatches 模式
  产出隐根包，与用户机内转换成功的包完全同源；CI 依赖补 file/coreutils/realpath shim，
  验证改为：无 /var/jb rpath、含 .jbroot rpath、有代码签名、.roothidepatch 存在、
  Pre-Depends 含 rootless-compat。
内容：全部 .xm/.h/.m、Makefile、AxsHoldLaunchBuild.mk、build.sh、AxsHoldLaunch.plist、control、
     Hooks/、Headers/、Sources/、Preferences 面板 plist/strings（packaging/overlay/）、
     packaging/package_beautify.sh、基线 deb（packaging/base/）、GitHub Actions 工作流。

beautify.108 变更（隐根包直装修复：Architecture 改为 iphoneos-arm64e）：
- 根因：roothide（隐根）包的标记是 Architecture: iphoneos-arm64e（bootstrap 布局标记，
  与 CPU 架构无关）。上一版隐根包只改对了扁平路径布局，Architecture 仍是 iphoneos-arm64

- 修正：打包脚本对隐根变体 control 执行 sed，Architecture 强制为 iphoneos-arm64e；
  CI 新增 Architecture=iphoneos-arm64e 断言；产物名同步为 _iphoneos-arm64e-roothide.deb。
- 依赖字段保持不变（mobilesubstrate/preferenceloader 由 roothide bootstrap 提供）；
  包内不带 .jbroot 链接（roothide 的 dpkg 安装时自动创建，与 RootHide Patcher 产物一致）。
- 效果：隐根包在 roothide Bootstrap 上直接安装，不再弹转换框。

beautify.107 变更（真正根治消散卡：Metal selector 修正）：
  - .106 日志证实 Metal 仍每次抛 unrecognized selector sent to
    AGXG15FamilyCommandQueue，说明 command buffer 的 selector 名字也是错的
  - 核对参考插件 dylib：commandBuffer 出现 2 次，newCommandBuffer 出现 0 次，
    真机可用的是 queue 的 commandBuffer（不是 newCommandBuffer）
  - 改为运行时探测：优先 commandBuffer，其次 newCommandBuffer，都没有则干净回退，
    不再抛异常；Metal 真正生效后不再创建 6000 层 UIView（卡顿消失）
  - CI/打包脚本同步断言 commandBuffer selector 与运行时探测日志

beautify.106 变更（根治消散卡：Metal 命令队列修复）：
  - 根因：.104 把 newCommandBuffer 错当 MTLDevice 方法，用 objc_msgSend 强绕过编译错误，
    真机运行时抛 unrecognized selector sent to AGXG15Device，Metal 每帧崩溃 → 一直回退 6000 层 UIView → 卡
  - 修正：新增 MTLCommandQueue 单例，从 queue 取 command buffer（Metal 正确 API）
  - 保留 objc_msgSend（SDK 头文件无法静态解析该 selector），但接收者改为正确的 queue
  - 效果预期：Metal 生效，14000 粒 GPU 一次 draw，主线程零负担（.107 再修 selector 名字）

beautify.105 变更（修复 Metal 彩砂无效果）：
  - 根因：iOS 纹理默认 storageMode=Private，replaceRegion 上传静默失败导致纹理全透明
  - 改为 MTLStorageModeShared，让 CPU 截图字节对 GPU 可见
  - 显式设置 CAMetalLayer.drawableSize 并 force layout，避免首帧 nextDrawable 为空
  - 新增首帧同步自检：Metal 真正画出第一帧才判定成功，否则自动回退 UIView，杜绝空白
  - 其余样式、速度滑块、面板配置均不变
